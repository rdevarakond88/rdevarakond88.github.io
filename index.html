Multi-agent healthcare records app

Agentic Healthcare

Designed and orchestrated an eight-agent Claude Code workflow to build an offline-first healthcare records app for semi-urban Indian clinics. No traditional dev team. 354 commits. The app shipped. It failed three times before working reliably.

What I learned

On failure modes

Agents fail at boundaries between them, not inside them. Every gap in the workflow was a handoff nobody owned.

On risk

Documenting a risk is not the same as gating on it. “Deferred” is not “handled.”

On fixes

Fixing a gap moves it. It doesn’t eliminate it. Every new agent boundary is a new potential failure point.

Sprint intelligence agents: enterprise delivery

Enterprise AI Jira / Rovo

Built three AI-powered agents inside Jira and Rovo to solve recurring pain points in a real delivery team: daily sprint health reports, cycle time analytics, and estimation accuracy analysis. None required a developer.

What I learned

On architecture

Adding more classification rules made the AI less reliable. The real fix was structural: use JQL for retrieval, AI only for interpretation. Misclassification became architecturally impossible.

On information

Stakeholders don’t need more data. They need fewer signals, only what requires a decision. Removing columns improved the report more than adding detail did.

On visibility

Cycle time and estimation accuracy were invisible problems. Not because the data didn’t exist, but because nobody had extracted it. AI made the invisible legible.

AI agents write their own status updates: done, tested, fixed. What I learned

On trust

An AI agent grading its own status update is the same blind spot as a person grading their own work. The fix isn’t a stricter prompt. It’s an independent check that never takes the agent’s word for it.

On self-checks

Even the safety net can be wrong. A check built specifically to catch the AI contradicting itself turned out to match nearby words, not meaning, and flipped a correct answer to wrong on the identical input, twice.

On fixing vs. hiding

The easy patch would have covered this one case and hidden the next one. Documenting a known limitation honestly beats a fix that only works on the bug you happened to catch.

How I know the agents are reliable

Independent scoring instead of trusting completion claims. PASS, PARTIAL, FAIL. No agent grades its own work.

MedRecord agent eval, v1.4

31 test cases scored across 5 modes, from isolated checks to a full pipeline run. PARTIAL counts as zero, not half credit. Blocked test cases (infrastructure failures, not agent failures) are excluded entirely.

What was testedScore
Invocation compliance: right agent, right moment70% Mostly compliant
Output quality: correct format and content50% Needs attention
Drift resistance: holds scope over long sessions80% Healthy
State-driven routing: reads project state correctly80% Healthy
End-to-end pipeline: all agents, real handoffs0% Critical gap
Finding Four of five modes test agents on their own: declare correctly, format correctly, hold scope, route correctly. They mostly do, 70–80%. The fifth mode connects them into a real pipeline, and that’s where it breaks. The clearest example: Security Agent rated a real authentication-exposure bug one severity tier too low, HIGH instead of CRITICAL, only once it was running inside the actual pipeline. That weaker signal is exactly why a different agent then marked the bug “resolved” on its own, before any re-check confirmed it. Individually competent agents, connected wrong, is a harder problem than one bad agent, and it’s invisible until you test the seams, not just the parts.

Status-drift-agent eval, v10

23 hand-labeled commits scored across 4 pipeline stages, from a single AI call to full deterministic rule enforcement. 6 historically unstable entries are re-run 3× independently, since a single run isn’t trusted as fact.

What was testedScore
Deterministic overrides: force the right status once a claim is actually disproven100% Reliable
Model judgment: final status matches the hand-labeled answer key91% Strong
Repeat-run stability: same commit, same answer, run independently83% Mostly stable
Self-check validator: flags a real contradiction, not a coincidence0% Critical gap
Unverifiable-claim detection: catches a bare, evidence-free process claimn/a Not built
Finding Four of five checks hold up well, 83–100%. The fifth is where it breaks: a validator built specifically to catch the AI contradicting itself turned out to have its own blind spot. It decides “is this a real problem” by checking whether two words sit close together in a sentence, not by understanding what the sentence means. Same commit, same true fact, worded two slightly different ways: one wording passed, the other flipped a correct answer to wrong, twice in three tries. Widening the rule would only catch this exact wording and miss the next one. A checker built to watch the AI needs its own watching. It’s invisible until you check the checker, not just the thing it’s checking.

03

On hallucination risk in ambiguous inputs

Tested four prompt patterns on a deliberately messy prescription with three ambiguous drug entries. No variant hallucinated, including the unstructured one with no guardrails. This isn’t a prompting finding. It’s a model selection finding. Before deploying AI in safety-critical contexts, benchmark the model, not just the prompt.

02

On the difference between rules and architecture

An AI classification agent kept misclassifying despite increasingly specific rules. Each new rule added prompt length, which hit the output limit, which broke something else. The real fix: use deterministic queries for retrieval, leave AI only for interpretation. You cannot instruct your way out of an architectural problem.

On where agentic systems fail
